# Проверка частей 14–21, включая 15Б — Codex, 01.11.2026

Проверены исходные изменения Antigravity из рабочей папки владельца относительно GitHub `main` (`1ab444d`). Прочитаны все девять записей: 14, 15, **15Б (в середине журнала)**, 16, 17, 18, 19, 20, 21. Исторические записи сохранены; их заявления о полной готовности не заменяют результаты этой проверки.

## Исправления

1. Восстановлены правила ИИ из проверенного `main`: переключатели администратора и личного ключа, разбор по кнопке. Убраны повторные запросы при записи перевода в историю и при перерисовке поиска словаря.
2. Исправлены направление карточки, передача языка, поиск английских слов и устаревшая карточка после смены запроса. Возвращены переключатели языков в словаре.
3. Сервер при недоступности ИИ читает реальные статические словари и примеры через `ASSETS`, а не собирает пустую карточку без лексикона. Неполные ответы не занимают вечный склад. Пересоздание сохраняет старую карточку до успешного ответа ИИ.
4. Прогрев не расходует пользовательский лимит, ограничен 20 карточками, прекращается при недоступности ИИ и продолжает с неудавшегося слова. Пустые словарные ответы больше не считаются успешно прогретыми.
5. Исправлены формы `arbeiten`, `tanzen`, `lesen`, отделяемые приставки (`aufstehen`), слабые существительные (`Student`). Неизвестный род не подменяется артиклем `der`; английским прилагательным не строятся немецкие таблицы.
6. В учёбу можно добавлять английские карточки с правильным языком. Убраны сгенерированные шаблоны вроде `This is a <любой глагол>` и «переводы», повторявшие исходное слово. Добавлены собственные переводы терминов Jobcenter, ведомств, банка и врача. Для слов без настоящего примера поле остаётся пустым.
7. Исправлен выход кнопок наборов за правый край на 360–390 px. Пустое упражнение больше не выглядит как успешно завершённая тренировка.
8. При первом обмене история загружается целиком; изменения избранного получают время правки, удаления передаются другому устройству. Поздние офлайн-правки не пропускаются из-за курсора чтения. Лимит серверных записей действительно ограничивает новые id.
9. Импорт проверяет формат до записи, сохраняет более свежий прогресс и настройки, обновляет открытые экраны и восстанавливает настройки числа новых слов. Кнопка синхронизации не выдумывает успешное время при сетевой ошибке.
10. LanguageTool сохраняет ведущие пробелы и правильные смещения исправлений. Недоступная проверка не объявляется успешной. Короткие лимиты выполняются атомарно в базе.
11. Автоматический журнал ошибок не передаёт текст исключения, поисковые параметры URL или неизвестные сегменты пути. Ручное описание проблемы остаётся добровольным текстом пользователя. На сервере добавлен лимит отправки отчётов.
12. Новые версии словарей используют отдельные кэши. Открытые данные сохраняются даже до установки Service Worker — это исправляет первый офлайн-запуск. Сбой сети не запоминается как вечное отсутствие слова.
13. Убрана зависимость главного экрана от всех учебных примеров: вместо всех колод он получает компактный список переводов. Большие учебные данные остаются в отдельном чанке.
14. SEO больше не принимает ссылки «форма → лемма» за самостоятельные статьи; исправлены небезопасные имена путей, повторы и уровни частоты. Генерируются 2000 немецких и 2000 английских страниц.
15. Упаковка OTA работает на Node.js без внешнего PowerShell/zip. Невозможность создать архив или превышение 25 MiB останавливает сборку, а не создаёт ложный успешный манифест.
16. Политика конфиденциальности на ru/de/en описывает реальный серверный кэш, передачу пароля по HTTPS, хранение ключей и границы удаления аккаунта. Объединены два конкурировавших окна «Что нового».
17. Скриншоты магазинов теперь снимаются с настоящего приложения. Прежний скрипт рисовал отдельные HTML-макеты. Ответы API в демонстрационных снимках подменены, что явно указано в скрипте и JSON отчёте.
18. В Android workflow перед сборкой APK запускаются регрессионные и API-тесты. Подпись APK, `MainActivity.applySystemBarInsets()`, `database_id`, `KEY_ENCRYPTION_SECRET`, проверенные `prompts.ts`, `request.ts`, `liveUpdate.ts` и логотип сохранены.

## Проверки и границы доказательств

- `npm test`: 67 тестов, 13 файлов. Проверяются реальные SQL на локальном SQLite: регистрация, вход Bearer без cookie, синхронизация EN-карточки с `deckId`, конфликты версий, ограничение записей, отказ удаления с неверным паролем и удаление всех связанных таблиц с правильным паролем. Это **локальный SQLite**, не проверка аккаунта владельца в production D1.
- TypeScript приложения и Functions; обычная сборка; Play-сборка и `cap sync android`; локальная компиляция Pages Functions.
- `node scripts/store-screenshots.mjs`: 30 проверок реального интерфейса, размеры 360/390 px и TV 1920×1080, светлая и тёмная темы, отсутствие исключений и горизонтального выхода страницы. API в этой проверке демонстрационные. Сводка: `store/screenshots/verification.json`.
- `node scripts/offline-smoke.mjs`: настоящий Service Worker, затем отключение сети в отдельном браузерном профиле; перезагрузка Haus и открытие словаря, учёбы, разговорника. Сводка: `store/screenshots/offline-verification.json`.
- `public/` около 86 MiB; крупнейший файл около 2.1 MiB. После SEO менее 8000 файлов, каждый меньше 25 MiB. OTA около 24.63 MiB; главный JS около 225 KiB gzip. Предупреждение Vite о чанке >500 KiB остаётся для больших данных.
- APK собирается и подписывается **только GitHub Actions**. Локальный keystore не открывался и не копировался. Результат Actions и факт обновления сайта фиксируются отдельным дополнением журнала после публикации.
