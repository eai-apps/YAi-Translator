## 3. Несколько общих ключей (резервные ключи)

Цель: если один бесплатный ключ Gemini или Groq кончился, сайт сам переходит на следующий.

- Ключи сайта берутся из двух мест: (а) переменные Cloudflare `GEMINI_API_KEY`, `GEMINI_API_KEY_2` … `_5`,
  так же для `GROQ_API_KEY*`, `DEEPL_API_KEY*`; (б) ключи, добавленные в админке (п. 5), — в D1.
- Новый модуль `functions/_lib/keypool.ts`: список рабочих ключей провайдера по очереди.
  Ответ 429 / квота исчерпана → ключ помечается «отдыхает до 00:00 UTC» (таблица `key_state`: provider, key_id,
  exhausted_until, last_error, last_used_at) и берётся следующий. Ошибка 401/403 → ключ помечается «неверный».
- `router.ts` и `classic/deepl.ts` используют пул вместо одного ключа. Ключ пользователя — как раньше, первым.
- `key_id` — первые 12 символов SHA-256 ключа; сам ключ в таблице состояний не хранится.

## 4. «Как переводят другие» — автоматическое сравнение

- Под основным переводом — сворачиваемый блок **«Как переводят другие»**.
- Для текста до 300 символов загружается сам, сразу после основного перевода, через `/api/compare`.
  Для длинного текста — кнопка «Показать». Сервис, который дал основной перевод, в списке не повторяется.
- У каждого варианта: название сервиса, текст, «копировать», «озвучить», **«Использовать этот вариант»**
  (подставляет его как основной перевод).
- `/api/compare` кэширует результат **каждого сервиса отдельно** (а не всей пачки), чтобы один упавший сервис
  не мешал кэшу остальных.
- Настройка в профиле: «Показывать другие переводчики автоматически» (по умолчанию включено, хранится в настройках).
- Старая кнопка «Сравнить переводчики» и `ComparePanel` убираются — их заменяет этот блок.

## 5. Админка

**Кто админ:** аккаунт, логин которого указан в секрете Cloudflare `ADMIN_LOGINS` (несколько логинов через запятую).
Пароль — обычный пароль этого аккаунта. Без `ADMIN_LOGINS` админки нет ни у кого.

- `GET /api/auth/me` отдаёт `isAdmin: true|false`. Ссылка «Админка» появляется в профиле только у админа.
- Страница `/admin` (ленивая загрузка, `React.lazy`), API `functions/api/admin/*` — каждый запрос проверяет сессию
  и права (`requireAdmin`), иначе 403. Все действия пишутся в таблицу `admin_log` (кто, что, когда).
- Вкладки:
  1. **Обзор:** зарегистрированные пользователи (всего, новые за сегодня / 7 / 30 дней), **посетители сайта**
     (уникальные за сегодня / 7 / 30 дней — считаются по хешу IP + дата, без хранения IP; отметка один раз в день
     при первом запросе к API, например в `/api/health`), активные аккаунты за 7 дней, переводы за сегодня по сервисам,
     доля ответов из кэша, запросы ИИ сегодня, популярные языковые пары. График за 30 дней
     (переводы и посетители по дням) — простым SVG без сторонних библиотек. Для этого — таблица `stats_daily(day, metric, value)`, счётчики увеличиваются
     в translate/word/explain/check/compare (одной записью `INSERT … ON CONFLICT DO UPDATE value = value + 1`).
  2. **Ключи сайта:** для каждого сервиса (Gemini, Groq, DeepL, Microsoft + регион, Google, Lara) — список ключей:
     источник («Cloudflare» — только просмотр; «Админка» — можно удалить), `••••1234`, состояние из `key_state`
     (работает / отдыхает до … / неверный), кнопки «Проверить», «Добавить ключ», «Удалить».
     Ключи из админки хранятся в таблице `site_keys` зашифрованными (`encryptKey` с контекстом `site:<provider>:<id>`).
     Новый ключ перед сохранением проверяется настоящим запросом.
  3. **Настройки:** дневной лимит бесплатных запросов ИИ на один IP (переопределяет `LIMITS.freeRequestsPerDay`),
     баннер-объявление на ru/de/en (показывается всем вверху сайта, можно закрыть крестиком) — таблица `settings(key, value)`.
  4. **Пользователи:** логин, дата регистрации, последний вход, число устройств, есть ли свои ключи;
     кнопки «Заблокировать» (поле `blocked` в `users`: вход и сессии отклоняются) и «Удалить» (с подтверждением).
- Все новые таблицы — в `schema.ts` и `migrations/0003_admin.sql`.
